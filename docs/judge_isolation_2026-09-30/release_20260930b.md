# Release dashboard-data-20260930b: re-judge five carried-over verdicts

## What the release is

Release `dashboard-data-20260930` (GPT-6.1 Sol) re-judged every case GPT-6.1 Sol re-opened with the isolated runner. It carried the other verdicts over from release 20260929 byte for byte. The [judge-isolation audit](REPORT.md) found five carried-over verdicts that cannot be presented as independent. This release re-judges those five with the same isolated runner and changes nothing else.

| Case | Why it is re-judged |
|---|---|
| `086 federal_refundable_credits` | Its judge launched a Workflow whose agents searched the repo and read this case's earlier published case note and row annotations. |
| `045 snap` | Its judge ran in a git checkout. The checkout's git status, injected into the judge's context, named this case's r33 exclusion and fix. |
| `014 federal_refundable_credits`, `015 federal_refundable_credits`, `015 head_medicaid_eligible` | No transcript holds the published verdict's text. |

No adjudication record covers any of the five, so the release cannot change a decision. The models, answers, references, exclusions and scores are release 20260930's.

## Commands

The judges must bill a subfleet Claude lane's own login, never the desktop login. Run the judge step inside a lane job:
- For a keychain-token lane, point `CLAUDE_CONFIG_DIR` at an empty directory kept for the lane, and pass the lane's token without printing it: `CLAUDE_CODE_OAUTH_TOKEN="$(~/bin/agent-secret get claude-quota-<lane account>)"`.
- Set `AUDIT_ACCOUNT` to the lane's account.

`scripts/run_audit_claude.sh` refuses to start on any other login.

```bash
export OPENBLAS_NUM_THREADS=1 PYTHONPATH="$PWD" PYTHONDONTWRITEBYTECODE=1
PB_BASE_STAGE=<release 20260930's stage>
PB_STAGE="$PWD/results/local/rejudge-20260930b"

"$PB_PY" scripts/finish_rejudge_20260930b.py --stage-dir "$PB_STAGE" --step prepare \
  --base-stage "$PB_BASE_STAGE"
CLAUDE_CONFIG_DIR=<lane config dir> CLAUDE_CODE_OAUTH_TOKEN=<lane token> \
  AUDIT_ACCOUNT=<lane account> \
  "$PB_PY" scripts/finish_rejudge_20260930b.py --stage-dir "$PB_STAGE" --step judge
"$PB_PY" scripts/finish_rejudge_20260930b.py --stage-dir "$PB_STAGE" --step triage
"$PB_PY" scripts/finish_rejudge_20260930b.py --stage-dir "$PB_STAGE" --step export
"$PB_PY" scripts/freeze_rejudge_20260930b.py --stage-dir "$PB_STAGE" --dry-run
"$PB_PY" scripts/freeze_rejudge_20260930b.py --stage-dir "$PB_STAGE"
```

The release also commits what any release that moves the tag and the judge provenance commits. Four judgments move to Claude Opus 5.5: one from Claude Opus 5 and three from GPT-5.6 Sol. 045 snap was already judged by Opus 5.5 and only gains a new judging date. The release therefore commits:
- the paper, re-rendered and re-pinned (`paper/render_paper.py`, then `scripts/freeze_snapshot.py --rendered-only`);
- the tests that pin the judge provenance counts or the frozen tag (`tests/test_paper_results.py`, `tests/test_notes.py`'s superseded releases and note metadata);
- a note entry for the release.

The freeze is a local build and uploads nothing. The release assets are `<stage>/predictions.csv.gz` and the staged payload renamed to `dashboard-data.json`, under tag `dashboard-data-20260930b`. After review and green CI, create the release, verify the downloaded sha256 against the pointer, and then merge.
